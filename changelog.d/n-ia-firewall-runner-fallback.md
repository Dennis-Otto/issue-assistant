### Added

- A runner in reserve for the AI. The analysis runs on `ubuntu-24.04-firewall`, GitHub's runner with the egress firewall, which is a technical preview: should GitHub rename or end it, every analysis of a repository waited in the queue for a day, and every later run of the same issue behind it, until a new release. Now the repository variable `ISSUE_ASSISTANT_AI_RUNNER` names another runner for the AI at once, such as `gh variable set ISSUE_ASSISTANT_AI_RUNNER --body ubuntu-24.04`. There Harden-Runner blocks every host but those of your `.github/egress-firewall.yaml` as the first step of the analysis, and the next step stops the job when a request to another host gets through, as in a private repository without a subscription of StepSecurity. The job `event` refuses a runner where nothing would block, such as a self-hosted one or `ubuntu-latest`, and `check` names it too when your CI passes the variable. With the variable unset, everything runs as before; [decision 0019](https://github.com/Dennis-Otto/issue-assistant/blob/main/docs/decisions/0019-a-runner-for-the-ai-when-the-firewall-runner-is-gone.md) explains what the fallback gives up.
- `check` now also refuses a host of `.github/egress-firewall.yaml` that is no host name in full, such as `localhost` or one with a port, since Harden-Runner takes the same hosts on the fallback runner.
