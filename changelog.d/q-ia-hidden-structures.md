### Bug fixes

- The AI no longer reads a cell of a table beyond the cells of its header, which GitHub drops without a trace, also in a quote, a list item or a footnote; a note says that such cells went. Every pipe that comes right after no backslash splits the row, as for GitHub, also in code, in a link or in a tag. A link or an image in such a cell no longer counts as an attachment. The cells that GitHub shows, a table in code or in an HTML block, and the rows after the end of a table still reach the AI.
- The AI no longer reads the source of a diagram, a map or a 3D model that GitHub draws, from fenced code or a `<pre>` of the languages `mermaid`, `geojson`, `topojson` and `stl`, where the page shows no source. Of a diagram, it reads what the drawing shows, without its comments, its title and description for screen readers and its tooltips; of a map, a model, and a diagram with a style or a theme of its own, a note in place of the source. A link in such a source no longer counts as an attachment. `Mermaid` with a capital letter and such a fence in longer code stay code, as GitHub shows them.
- The AI no longer reads math whose TeX could draw text as nothing, such as a transparent colour, a comment from `%` or a `\label`: math with a backslash, a `%` or an `&` goes, with a note in its place, in every form that GitHub reads as math, also with `\$` or an entity in place of a dollar sign and in fenced code of `math`. Plain math such as `$x^2$` and dollar signs that GitHub shows as text, such as `it costs $5 and $6`, stay.
- A comment of the assistant can no longer form math or a drawing: fenced code of `mermaid` or `math` in an answer of the AI is posted as code of the language `text`, and a dollar sign that could start or end math as a code span.
- A notice in the log counts the cells, the parts of drawings and the math that went.
