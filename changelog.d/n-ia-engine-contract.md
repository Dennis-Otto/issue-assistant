### Security

- Gemini keeps to its tools that read again. The Gemini CLI takes its system settings, which leave it only the tools that read files of the checkout and turn off MCP servers, extensions, agents, skills, hooks, telemetry and checkpoints and set its turns, only from a folder that root owns. On GitHub's runners they were in a folder of the runner's user, so it skipped them with no more than a warning and ran without them. Now `analyze` and `evaluate` write them with sudo into a folder of root's below `/etc/issue-assistant`, and stop rather than run Gemini without them; `evaluate` runs Gemini only on Linux, macOS or WSL. A new check, *engine contracts*, found it: on every update of an engine and every week, it runs the pinned versions of the engines without a key and fails when an input of an engine's action, a flag of its command line or a key of its settings that keeps it to reading is gone, or when Gemini no longer refuses broken settings in the file that it should read.
