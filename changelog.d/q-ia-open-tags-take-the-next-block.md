### Bug fixes

- The AI no longer reads a paragraph, a heading or a table whose start tag a tag above it took. Where an HTML block ends a tag without its `>`, such as `<div` before a blank row, or an instruction such as `<div><?`, GitHub reads the start tag of the next block into it, so that a drawing in that paragraph stays open past its end, and a line break, a rule, an image or a `<source>` in it hides the rest of the issue, as do a video, the brackets of ruby and a date without their end tags: `<div`, a blank row, `<svg><br>Plugh`, a blank row and `more words` show only a line break. The assistant now leaves that text out of the issue, its comments, the excerpts and the attachments, and the search for older issues, the language of the comments, the area and whether a pull request denies that it fixes an issue read it the same way. The same holds for a video, the brackets of ruby and a date after a tag that closes their paragraph, such as `<div>`, `<hr>` or `</p>`.
- An instruction or a declaration on a later row of a `<div>` block, such as `<?x`, now ends at the end of that block, as on GitHub, so the AI reads the text of the next paragraph that GitHub shows.
- On the safe side, the AI also misses some text that GitHub still shows there, such as after an enclosing `</div>` or `</details>` and after the end of a quote around the block.
