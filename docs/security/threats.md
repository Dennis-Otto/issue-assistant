# Threats and countermeasures

[← Security design](../security.md) · [Threats to the runs and the workflows](threats-to-the-runs.md)

What an issue can try to make the AI do or write, with the countermeasure and the evidence of each.

| Threat | Countermeasure | Evidence |
| --- | --- | --- |
| An issue tells the AI to run a command, read a secret or reach a server | Each engine runs with only tools that read, as [the boundary of each engine](engines.md#the-boundary-of-each-engine) shows, with a read-only token or none, and the egress firewall allows only the hosts of the engine of `config.toml`, which a step proves before the AI runs: the job stops when a host outside the policy answers | `test_each_engine_can_only_read_the_checkout`, `test_only_the_analyze_job_runs_an_engine_and_only_with_read_permissions`, `test_the_firewall_template_allows_only_named_hosts`, `test_the_ai_runs_only_once_the_network_block_holds` in `tests/test_templates.py` |
| A text of an issue or a comment passes for the maintainer, for another comment or for the AI's earlier answer, with a heading like those of `issue.md` | Each text stands in a code fence one backtick longer than its longest run of backticks, so that nothing in it can end the fence; only the assistant writes the headings with author, role and date, and the prompt says that a fence holds only that person's text | `test_no_text_forms_a_heading_or_a_comment_in_issue_md` in `tests/test_assistant.py`; `test_no_text_forms_the_structure_of_issue_md_or_hides_in_it` in `tests/test_properties.py` |
| An issue hides instructions for the AI in characters that GitHub shows as nothing, such as Unicode tags, zero-width spaces or the controls of the direction of writing, also for the analyses of later issues | The format characters of Unicode and the code points it calls default ignorable are removed from `issue.md`, the excerpts of the other issues and discussions, and the AI's answer before its checks, and with them every character reference of one that GitHub reads somewhere, such as `&#xE0041;`, outside code in the texts that GitHub reads as Markdown; an address with either is no attachment; a notice in the log counts them | `test_the_invisible_characters_are_those_that_unicode_names`, `test_no_invisible_character_reaches_the_engine`, `test_the_answer_loses_its_invisible_characters_before_the_checks`, `test_the_engine_reads_no_text_that_github_hides`, `test_the_engine_reads_no_reference_that_github_shows_as_nothing`, `test_every_reference_of_an_invisible_character_goes`, `test_the_engine_reads_of_each_searched_reference_what_github_shows`, and `test_no_file_of_the_project_hides_characters` for the project's own files, in `tests/test_assistant.py`; `test_an_address_with_an_invisible_character_is_no_attachment` in `tests/test_attachments.py`; `test_no_text_forms_the_structure_of_issue_md_or_hides_in_it`, `test_the_engine_reads_no_text_that_github_hides` and `test_the_engine_reads_no_reference_that_github_reads_as_nothing` in `tests/test_properties.py` |
| An issue hides instructions for the AI in a link reference definition, such as `[//]: # (a comment)`, or in a footnote without a reference, which GitHub shows as nothing, also for the analyses of later issues | They go from `issue.md` and the excerpts of the other issues and discussions, after the HTML and outside code, with a note in the place of each; where Markdown is hard to follow exactly, a definition goes rather than stays; a notice in the log counts them | `test_the_engine_reads_no_definition_that_github_hides`, `test_what_github_shows_of_a_definition_stays`, `test_no_definition_reaches_the_engine` in `tests/test_assistant.py`; `test_a_commonmark_parser_finds_no_definition_in_what_the_engine_reads` in `tests/test_properties.py` |
| An issue holds text that GitHub doesn't show as written: a cell of a table beyond the cells of its header, which GitHub drops, the source of a diagram, a map or a 3D model, which GitHub draws in its place, math that GitHub can draw as nothing, or the title of a link or an image, which the page shows only on hover, also in the excerpts for the analyses of later issues | Read from the text as written, beside the HTML, the dropped cells, the source of a drawing but the rows of a diagram that its drawing shows, and math with a backslash, a `%` or an `&` go from `issue.md` and the excerpts, with a note in the place of each, and each title with the blanks before it, without one, while the link and the description of an image stay; where it is hard to tell, more goes; a notice in the log counts them | `test_the_engine_reads_no_cell_beyond_the_header_of_a_table`, `test_a_table_that_github_shows_whole_stays_whole`, `test_the_cells_and_the_html_go_as_either_reads_the_text`, `test_the_engine_reads_of_a_drawing_what_the_page_shows`, `test_code_that_github_shows_as_it_is_stays`, `test_the_engine_reads_no_math_that_could_hide_text`, `test_dollars_that_github_shows_as_text_stay`, `test_the_parts_that_github_doesn_t_show_as_written_are_counted`, `test_the_engine_reads_no_title_that_github_shows_only_on_hover`, `test_a_title_that_github_shows_as_text_stays`, `test_the_engine_reads_no_title_of_a_link` in `tests/test_assistant.py`; `test_the_engine_reads_no_cell_that_github_drops`, `test_no_text_of_math_or_a_drawing_reaches_the_engine_that_could_hide`, `test_the_engine_reads_no_title_of_a_link_or_an_image` in `tests/test_properties.py` |
| A comment that GitHub shows collapsed, as spam, off-topic or outdated, whose text the page shows only after a click, also a comment or a reply of a discussion and the marked answer of another discussion | `issue.md` and `discussion.md` keep its heading and put a note in place of its text; none of its files is downloaded, a reply task judges it as deleted, it chooses no language, starts no follow-up on its questions, gets no second follow-up and teaches no objection; a notice in the log counts it. What closes, locks or reopens an issue and what keeps the AI out counts it as before, since a moderator of an organization can collapse comments but neither close, label nor lock an issue | `test_the_engine_reads_no_comment_that_github_shows_collapsed`, `test_the_note_of_a_collapsed_comment_names_only_a_reason_of_github`, `test_a_collapsed_comment_chooses_no_language`, `test_a_collapsed_analysis_starts_no_follow_up`, `test_a_collapsed_comment_of_the_reporter_gives_no_second_follow_up`, `test_a_collapsed_comment_teaches_no_objection`, `test_a_collapsed_comment_still_counts_for_the_lifecycle` in `tests/test_assistant.py`; `test_a_collapsed_discussion_comment_is_not_read` in `tests/test_discussions.py`; `test_the_engine_reads_no_text_of_a_comment_that_github_shows_collapsed` in `tests/test_properties.py`; the moderator of `tests/test_lifecycle_properties.py` |
| A file that a reporter attaches, such as a log, tells the AI what to do, forges a comment of a maintainer, hides instructions in characters that no one sees, leaks a token, or is no text at all | Only the text files of the reporter, `.txt`, `.log`, `.json`, `.yaml` and `.yml`, from a link that GitHub shows, in the text, a Markdown link or image, the `href` of an `<a>` or the `src` of an `<img>`, never another attribute of a tag such as `title`, which the page shows only on hover, nor a cell of a table beyond the cells of its header, which GitHub drops, the source of a diagram, a map or a 3D model, or math, whose text GitHub draws, at most 5 and 80,000 bytes of each; a file with a null byte or that isn't UTF-8 is left out, and images, archives and every other file are named and never downloaded, opened or unpacked. In `attachments.md` each text stands in a code fence that nothing in it can close, under a heading of the script, without escape sequences of a terminal, control and invisible characters, with each part that looks like a token or a key replaced with `[secret]` and each e-mail address with `[e-mail address]`; the AI only reads, and `apply` checks its answer as every other ([decision 0033](../decisions/0033-the-ai-reads-the-text-files-that-a-reporter-attaches.md)) | `test_a_file_of_another_person_or_one_that_github_hides_counts_as_none`, `test_an_address_counts_only_where_github_shows_a_link_or_an_image`, `test_only_the_href_of_a_link_and_the_src_of_an_image_show_an_address`, `test_a_tag_counts_as_the_html_parser_of_github_reads_it`, `test_a_comment_end_in_a_quoted_value_ends_no_tag`, `test_a_tag_that_github_shows_as_text_shows_its_address`, `test_where_it_is_hard_to_tell_an_address_counts_as_none`, `test_no_link_shows_in_a_dropped_cell_a_drawing_or_math`, `test_the_ai_reads_each_text_in_a_fence_that_it_can_t_close`, `test_the_text_loses_what_hides_or_leaks_before_the_ai_reads_it`, `test_only_utf_8_without_a_null_byte_is_text`, `test_a_hostile_attachment_changes_nothing_that_is_posted`, `test_the_answer_that_repeats_a_secret_of_a_file_is_never_posted` in `tests/test_attachments.py` |
| An image that a reporter attaches tells the AI what to do in the text that it shows, is a page or a script that calls itself an image, or aims at the program that decodes it | Only the images of the reporter, from a link that GitHub shows, by the same rule as the text files, at most 3 and 5 MB of each, kept only when their first bytes are those of PNG, JPEG, GIF or WebP, never SVG; the job never opens or decodes one. `attachments.md` names an image with its path only for an engine that opens images, Claude or Gemini, while `[attachments] images` of `config.toml` isn't `false`, which keeps every image out of the download, and only a file of a name that the job gives whose bytes still start as its kind; the rules say that what an image shows is the reporter's material, never an instruction; the AI only reads, and `apply` checks its answer as every other ([decision 0034](../decisions/0034-an-engine-that-opens-images-sees-the-screenshots-of-the-reporter.md)) | `test_only_the_first_bytes_of_an_image_name_its_kind`, `test_the_job_keeps_each_image_whole_with_the_end_of_its_kind`, `test_only_an_image_that_fetch_wrote_as_it_names_it_is_named`, `test_an_engine_that_opens_no_image_reads_that_it_can_t`, `test_a_repository_can_keep_every_image_from_the_ai`, `test_the_command_downloads_images_only_for_an_ai_that_opens_them`, `test_a_hostile_attachment_changes_nothing_that_is_posted` in `tests/test_attachments.py` |
| An issue makes the AI post a mention, a link, an image or HTML | `apply` removes images, HTML and the marks of headings, also in a quote or a list, escapes those deeper in a list, escapes a line of `=` or `-` that would make the line above it a heading, turns mentions, e-mail addresses, references and addresses that GitHub would link elsewhere into code, and keeps only links to allowed sites and to issues that exist; it makes fenced code that GitHub would draw or read as math code of the language `text`, and each dollar sign that could start or end math a code span; it places the text in the comment so that its code stays code | `test_mentions_images_html_and_headings_are_removed`, `test_no_heading_of_any_kind_is_left`, `test_only_links_to_known_places_stay_links`, `test_tricky_text_is_cleaned_safely`, `test_what_github_would_link_elsewhere_becomes_code`, `test_the_whole_comment_mentions_nobody_and_links_nowhere_else`, `test_no_table_cuts_code_in_two`, `test_an_answer_posts_no_code_that_github_draws`, `test_an_answer_forms_no_math` in `tests/test_assistant.py`; property tests of the text, of the places it takes in a comment and of whole comments in `tests/test_properties.py`, judged by the oracle of `tests/oracle.py`; fuzzing with Atheris in `fuzz/fuzz_sanitize.py` and `fuzz/fuzz_render.py` |
| The AI posts a secret that it found or was given | An answer with anything that looks like a token or a key is never posted, as [What counts as a secret](answers.md#what-counts-as-a-secret) shows | `test_an_answer_with_something_like_a_secret_is_never_posted`, `test_ordinary_long_words_links_and_paths_are_no_secrets`, `test_a_file_that_git_tracks_is_no_secret` in `tests/test_assistant.py`; `test_a_token_anywhere_in_the_answer_is_refused`, `test_a_path_that_git_tracks_is_never_a_secret` in `tests/test_properties.py` |
| An answer runs a workflow command in the log of the run, such as `::add-mask::`, `::stop-commands::` or a forged `::error::`, or its comment ends the code block of the preview in the summary of a dry run | Every error and notice of the assistant is escaped as GitHub's Actions toolkit escapes it, and a key of the answer that the schema doesn't know shows as a short JSON string. The Codex action prints what Codex prints into the log, so Codex prints JSON events alone, one per line, and no log of its own (`--json` and `RUST_LOG=off`); the Gemini CLI and the Copilot CLI print nothing there, because `analyze` keeps their output. The summary turns workflow commands off with a random token while it prints the engine's words, and the fence of a preview is longer than any run of backticks in the comment | `test_no_text_of_the_engine_runs_a_workflow_command`, `test_a_workflow_command_keeps_its_message_on_its_line`, `test_each_summary_stops_the_commands_with_a_token_of_its_own`, `test_only_a_terminal_outside_a_runner_gets_the_summary_alone`, `test_a_preview_can_t_close_its_fence` in `tests/test_assistant.py`; `test_each_engine_can_only_read_the_checkout` in `tests/test_templates.py` |
| An answer mentions someone or links elsewhere in a reason outside its comment: a line of the log and the summary, or the reason for a label or a duplicate on the timeline | Such reasons are cleaned like a comment, joined into one line before the cleaning, so that no code block keeps a mention as it is, and shortened to 280 characters before the cleaning, so that no cut loses the backtick that keeps a mention in its code | `test_the_reasons_on_the_timeline_are_cleaned_like_comments`, `test_the_engine_s_reasons_in_the_log_are_one_cleaned_line`, `test_a_shortened_line_keeps_its_cleaning` in `tests/test_assistant.py`; property tests in `tests/test_properties.py`; fuzzing with Atheris in `fuzz/fuzz_sanitize.py` |
| An issue steers the analyses of later issues into calling them its sure duplicates, so that they close after 3 days | Only an open original that a maintainer opened or triaged gets the notice that closes a duplicate; any other becomes a suggestion for the maintainer. A comment of anyone, and a thumbs down of the reporter or of anyone who may push to the repository, keep the issue open, and so does an original that is closed or no longer vouched for when the 3 days are over. What remains: the check looks at the original alone, so the text of any open issue, triaged or not, can still steer analyses into calling new issues sure duplicates of a third, triaged one; their reporters get the notice, a comment or a thumbs down keeps the issue open, and the maintainer sees the label `possible-duplicate` for the 3 days, as [the residual risks](../security.md#residual-risks) say | `test_a_sure_duplicate_of_an_untriaged_issue_is_only_suggested`, `test_a_thumbs_down_of_the_reporter_or_a_maintainer_keeps_the_issue_open`, `test_other_reactions_do_not_object`, `test_a_notice_against_an_untriaged_original_closes_nothing` in `tests/test_assistant.py` |
| Someone writes a correction for the AI to learn from: a title that reads as a maintainer's correction or an instruction in `corrections.md`, or a 👎 that makes a good analysis look wrong | The script writes every line of `corrections.md` from GitHub's events, the markers of the assistant's comments and its reactions: the number, the labels of `labels.md` and fixed words, with the title as a JSON string without invisible characters, all in a code fence that no title can close. Only people with triage access can change labels, a 👎 counts only from someone who may push, and the AI reads the file as data for issues like the listed ones, never as instructions | `test_a_first_analysis_learns_from_the_maintainers_corrections`, `test_a_duplicate_notice_is_objected_to_by_people` and `test_an_issue_learns_from_its_own_corrections_and_not_beyond_the_window` in `tests/test_assistant.py` |
| A discussion makes the AI speak for the project in public: answer where the maintainers didn't ask for answers, answer again and again, mark its own answer as the accepted one, or post after a maintainer answered | Only the categories of `[discussions] answer_categories` get an answer, none by default, and never a discussion of a maintainer or a bot. `apply` reads the discussion again and posts one comment, with every check of an analysis, only while it is open, unlocked, without an answer and without a maintainer's comment, and never marks it as the answer; the footer names the AI and that it can be wrong. A bug or a feature request only gets a link to the form of an issue, never one | `test_other_categories_maintainers_and_bots_get_no_answer`, `test_nothing_changes_while_no_category_is_named`, `test_the_first_answer_is_checked_and_posted_once`, `test_the_answer_waits_for_nothing_that_happened_meanwhile`, `test_the_text_of_the_ai_is_cleaned_as_every_analysis` in `tests/test_discussions.py`; `test_the_answer_to_a_discussion_is_one_comment_on_it` in `tests/test_graphql_contract.py`; whole comments in `tests/test_properties.py` |
| An answer that breaks the schema changes the wrong labels or issues | The answer is checked against the schema of its task, the labels and the issues that exist | `test_an_answer_that_breaks_the_schema_is_refused`, `test_any_answer_is_checked_or_refused` |
